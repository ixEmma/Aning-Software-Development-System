# Frontend design review template

Copy the following sections into the project PR template or review description; adapt to existing project conventions.

## Frontend change level
Level: Not applicable / Level 1 / Level 2 / Level 3

## Approved scope and non-goals
Describe affected routes/components and what stays untouched.

## Design references and preservation
Identify current project design system, approved brand assets, and any references. For Level 3, record approved reference-stack decision and attribution/license basis as relevant.

## Functional verification
List actual commands, browser states or integration checks run, and results.

## Visual and accessibility evidence
Include comparable desktop/mobile views, interaction states, contrast/focus evidence where relevant, and an explicit `Not verified` for gaps. Level 1 may state why screenshots are unnecessary.

## Human checkpoints
Record owner review for material departures and Level 3 reference-stack and final visual approvals. A checked box alone is not approval.

## Delivery state
Record commit SHA, pending follow-ups, and whether merged, deployed, or production-verified. Never conflate these states.
